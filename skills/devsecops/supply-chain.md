## SBOM — Software Bill of Materials (ADR-0020)

Every release produces a CycloneDX v1.6 SBOM generated by Syft.

```shell
# Generated in CI (sbom.yml workflow) on every tagged release
syft packages . \
  --output cyclonedx-json \
  --file sbom.json

# Attach to GitHub Release as artifact
gh release upload v$VERSION sbom.json
```

The SBOM lists every dependency with:

- Package name and version
- Declared license
- Source location (PyPI, GitHub, etc.)
- CVE exposure at time of build

## Dependency Pinning Rules

### Python dependencies (ADR-0022)

```
requirements.in   ← human-managed; abstract constraints only (e.g. anthropic>=0.25)
requirements.lock ← generated; exact versions + hashes (never edited manually)
```

```shell
# Generate/update lock file
pip-compile --generate-hashes --output-file requirements.lock requirements.in

# Install from lock file (CI and production)
pip install --require-hashes -r requirements.lock
```

All packages in `requirements.lock` must include `--hash=sha256:...`. Installing without hashes is rejected in CI.

### Docker base images

```dockerfile
# WRONG — mutable tag
FROM python:3.12-slim

# CORRECT — pinned to digest
FROM python:3.12-slim@sha256:a1b2c3d4e5f6...
```

Pin digests, not tags. Tags are mutable; digests are immutable. Update via Dependabot or manual review — never automatically accept a new digest without verifying the release notes.

### GitHub Actions

```yaml
# WRONG — mutable tag
uses: actions/checkout@v4

# CORRECT — pinned to commit SHA
uses: actions/checkout@11bd71901bbe5b1630ceea73d27597364c9af683  # v4.2.2
```

All third-party Actions pinned to a full commit SHA. The comment documents which tag the SHA corresponds to.

## CVE Triage SLA (spec 15)

| Severity | SLA to patch or accept-risk | Blocks release                  |
| -------- | --------------------------- | ------------------------------- |
| Critical | 24 hours                    | **Yes** — no accepted-risk path |
| High     | 5 business days             | Yes                             |
| Medium   | 30 calendar days            | No                              |
| Low      | 90 calendar days            | No                              |

**Critical CVEs have no accepted-risk path** — the dependency must be patched or replaced.

```shell
# Run CVE scan (CI gate G11 — also run locally before PR)
pip-audit --requirement requirements.lock --format json --output audit.json

# Check for Critical findings
jq '[.[] | select(.vulnerabilities[].fix_versions != null and
    .vulnerabilities[].aliases[] | startswith("CVE"))] | length' audit.json
```

## License Allowlist and Prohibited List (spec 15)

### Allowed licenses

| License                    | Notes           |
| -------------------------- | --------------- |
| MIT                        | No restrictions |
| Apache 2.0                 | No restrictions |
| BSD 2-Clause               | No restrictions |
| BSD 3-Clause               | No restrictions |
| ISC                        | No restrictions |
| Python Software Foundation | CPython only    |

### Prohibited licenses (require Legal review before use)

| License                             | Reason                                           |
| ----------------------------------- | ------------------------------------------------ |
| GPL v2/v3                           | Copyleft — may require source disclosure         |
| AGPL                                | Network use triggers copyleft                    |
| LGPL                                | Dynamic linking exception — case-by-case         |
| SSPL                                | MongoDB open-source license — highly restrictive |
| Commons Clause                      | Restricts commercial use                         |
| Proprietary / "all rights reserved" | Requires explicit license agreement              |

```shell
# License audit (run before adding new dependencies)
pip-licenses --format=json --output-file licenses.json
# Review output for any prohibited licenses before merge
```

## SLSA Level 2 Evidence (ADR-0020)

SLSA Level 2 requires provenance: machine-generated, authenticated by the CI/CD pipeline.

| SLSA requirement         | Evidence                                                    |
| ------------------------ | ----------------------------------------------------------- |
| Source identified        | GitHub repository + commit SHA in every build               |
| Build scripted           | `.github/workflows/sbom.yml` — no manual build steps        |
| Provenance generated     | `sigstore/gh-action-sigstore-python` signs SBOM with Cosign |
| Provenance authenticated | Sigstore transparency log; verifiable by any party          |
| Artifact integrity       | SHA-256 digest in provenance matches deployed artifact      |

Provenance verification:

```shell
cosign verify-attestation \
  --type slsaprovenance \
  --certificate-identity-regexp "https://github.com/valdomirosouza/.*" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com" \
  ghcr.io/valdomirosouza/agentic-copilot:v0.3.0
```

## Dependabot Configuration

```yaml
# .github/dependabot.yml
version: 2
updates:
  - package-ecosystem: pip
    directory: /
    schedule:
      interval: weekly
    open-pull-requests-limit: 5
    labels:
      - "type:chore"
      - "security"

  - package-ecosystem: github-actions
    directory: /
    schedule:
      interval: weekly
    open-pull-requests-limit: 5
    labels:
      - "type:ci"
```

Dependabot PRs for Critical/High CVEs must be merged within the SLA window. Non-security updates are batched weekly.
